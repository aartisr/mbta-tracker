Design notes

Trust begins by showing what the system knows—and what it does not.

MBTA Tracker is designed around the small, pressured decisions that happen before a rider boards: where to go, whether to wait, and how much confidence to place in the answer.

Search before interpretation

A rider may know a route, a stop, an intersection, a vehicle, or simply a familiar place. The live tool treats those as valid beginnings rather than requiring a map-first workflow. A compact result is shown before optional operational detail.

Time before metadata

Arrival and next action carry the greatest urgency. Route context, accessibility signals, crowding estimates, and other detail should support that decision rather than compete with it. This is the practical application of progressive disclosure in the product.

Transparency is part of usefulness

Realtime transit data can be late, partial, or unavailable. The tracker surfaces connection and freshness state because a polished answer without provenance can be more harmful than an incomplete answer with a clear limitation.

Scope note: these are research-informed design choices, not claims that the interface has already been validated by a controlled rider study. Crowding is heuristic when live occupancy is unavailable, and accessibility has not yet received a formal end-to-end audit.
